# ARCHITECTURE — Technology decisions

This file records **technical** decisions: components, technologies, interfaces and
file layout. Each decision (ADR) has an ID, the decision, and why.

## Overview

```
 End user (browser)
        │ HTTP :800
        ▼
┌──────────────────────┐   HTTP POST /predict    ┌──────────────────────────┐
│ Frontend container   │ ──────────────────────▶ │ Backend container        │
│ Streamlit (app.py)   │  host.docker.internal   │ FastAPI + Uvicorn :8000  │
└──────────────────────┘        :8000            │ loads model/ at startup  │
                                                 └────────────┬─────────────┘
                                                              │ mlflow.sklearn.load_model
                                                 ┌────────────▼─────────────┐
                                                 │ model/ (MLflow format)   │
                                                 │ created by train.py      │
                                                 └──────────────────────────┘
```

## Target file layout

The agent writes the code under `output/src/`:

```
output/src/
├── backend/
│   ├── requirements.txt
│   ├── Dockerfile
│   ├── train.py        # trains and saves the model to backend/model/
│   └── app.py          # FastAPI app: /health, /predict
└── frontend/
    ├── requirements.txt
    ├── Dockerfile
    └── app.py          # Streamlit page
```

`backend/model/` is generated by running `train.py`; it is **not** written by the
agent.

---

## ADR-01 Python 3.13 everywhere

Both services use the `python:3.13` Docker base image.
*Why:* one language for the ML, the API and the UI; one version to support.

## ADR-02 Two services, two images

`backend` and `frontend` are separate folders, each with its own `Dockerfile` and
`requirements.txt`. They share no code.
*Why:* they can be built, deployed and scaled independently, like in production.

## ADR-03 Dockerfile pattern

Both Dockerfiles follow the same steps, in this order:

```Dockerfile
FROM python:3.13
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD [...]
```

*Why:* copying `requirements.txt` first lets Docker cache the dependency layer, so a
code change does not reinstall everything.

## ADR-04 Model: scikit-learn LogisticRegression on a toy dataset

- Data: `sklearn.datasets.make_classification(n_samples=300, n_features=4, n_informative=3, n_redundant=1)`.
- Split: `train_test_split(test_size=0.2, stratify=y)`.
- Model: `LogisticRegression(max_iter=500, n_jobs=1)`.
- Metric: `accuracy_score` on the test split.

*Why:* trains in under a second, no data download, and has `predict_proba`.

## ADR-05 MLflow model format, saved to the local filesystem

The model is saved with `mlflow.sklearn.save_model(model, <backend>/model)` and loaded
with `mlflow.sklearn.load_model(<backend>/model)`. The path is computed from the
script's own folder (`os.path.dirname(__file__)`), not from the working directory.
No tracking server, no registry.
*Why:* a standard, portable model format with the least infrastructure. Using the
script's folder makes it work both locally and in `/app` inside Docker.

## ADR-06 Backend: FastAPI + Uvicorn on port 8000

- `FastAPI(title="Minimal MLflow + FastAPI", version="0.1.0")`.
- Served by `uvicorn app:app --host 0.0.0.0 --port 8000`.
- Request/response models with **Pydantic** `BaseModel`:
  - `PredictRequest { features: List[float] }`
  - `PredictResponse { predicted_class: int, probability: float }`
- The length check (4 features) is done **inside the endpoint**, not in the Pydantic
  model.

*Why:* FastAPI gives validation and `/docs` for free. Checking the length by hand
avoids differences between Pydantic v1 and v2 constraint syntax.

## ADR-07 Load the model once, at startup

The model is loaded in a `@app.on_event("startup")` handler into a module-level
global `model`. If `model/` does not exist, the handler raises `RuntimeError`.
*Why:* loading per request is slow; failing at startup surfaces a missing model
immediately (fail fast).

## ADR-08 Prediction

- Convert the features to `numpy.array(features, dtype=float).reshape(1, -1)`.
- `probability = float(model.predict_proba(x)[0, 1])`
- `predicted_class = int(model.predict(x)[0])`
- Any exception during prediction → `HTTPException(400, "Prediction failed: <e>")`.

*Why:* casting to built-in `int`/`float` makes the values JSON-serialisable.

## ADR-09 Frontend: Streamlit on port 800

Run with `streamlit run app.py --server.address=0.0.0.0 --server.port=800`.
*Why:* a web UI in pure Python with very little code.

## ADR-10 Frontend → backend communication

- Library: `requests`.
- Call: `requests.post("http://host.docker.internal:8000/predict", json=payload, timeout=5)`
  followed by `raise_for_status()`.
- Exceptions handled in this order: `requests.Timeout`, `requests.ConnectionError`,
  `requests.RequestException`.
- The backend URL is a constant in the code (no environment variables in this
  iteration).

*Why:* without Compose/Kubernetes, containers talk through the Docker host.
`host.docker.internal` works on macOS/Windows directly and on Linux with
`--add-host=host.docker.internal:host-gateway`. The order of `except` clauses
matters: `Timeout` and `ConnectionError` are subclasses of `RequestException`.

## ADR-11 Dependencies are not pinned

| Service | `requirements.txt` |
|---|---|
| backend | `mlflow`, `fastapi`, `uvicorn` |
| frontend | `requests`, `streamlit` |

`scikit-learn`, `numpy` and `pydantic` come in as dependencies of `mlflow` and
`fastapi`.
*Why:* simplest setup for a class. Pinning versions is a known next step for
reproducible builds.

## ADR-12 No shared configuration, no orchestration

Ports and URLs are hard-coded (8000, 800, `host.docker.internal`). Containers are
started by hand with `docker run`.
*Why:* time constraint of the session; Docker Compose would be the next step.

## Commands (reference)

```bash
# backend
cd output/src/backend
docker build -t ub-agile-data-science-backend .
docker run -v .:/app ub-agile-data-science-backend:latest python train.py
docker run -v .:/app -p 8000:8000 ub-agile-data-science-backend:latest

# frontend
cd output/src/frontend
docker build -t ub-agile-data-science-frontend .
docker run -p 800:800 --add-host=host.docker.internal:host-gateway ub-agile-data-science-frontend:latest   # Linux
docker run -p 800:800 ub-agile-data-science-frontend:latest                                               # macOS / Windows
```
